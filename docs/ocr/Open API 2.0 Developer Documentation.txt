Open API 2.0 Developer Documentation
# Instruction
Through Open API service, Buyers and Seller can integrate third-party ERP systems or self-developed systems with GIGAB2B to access relevant data and develop custom applications.
Currently, Buyers can apply for Open API connection by accessing: Buyer Central — APIs — Connection Options tab — Open API. Once the application is successfully submitted and proceeds to active status, Buyers can view the details in the Active Connections tab to obtain their Client ID and C
lient Secret. For Sellers requesting Open API integration, they are required to contact the Marketplace Online Customer Service for activation and obtain their Client ID and Client Secret.
Connection Process:
1.Buyers: Apply for Open API connection via GIGAB2B and obtain their API Key.
2.Sellers: Request Open API connection by contacting Marketplace Online Customer Service. (Note: Currently only On-Site Sellers are supported.)
3.Configure common parameters according to this documentation and set up signatures using the provided Signature Rules.
4.Test and deploy the integration. If Buyers require GIGAB2B 's assistance during testing, contact Marketplace Online Customer Service to connect with technical support.
# Version Notes
The rules mentioned in this documentation apply to all Open API 2.0 interfaces. Developers are advised to migrate to this version as soon as possible, as it offers more robust features, standardized error messages, and richer feedback. The legacy version (Open API 1.0) will soon be deprecated a
nd will no longer be accessible.
API Keys obtained by Buyers before the release of the new version (prior to August 28, 2025) on the GIGAB2B can be used to access all Open API 2.0 interfaces, with few exceptions for those who applied offline. If your existing API Key fails to call Open API 2.0 interfaces, please reapply for Open
API connection on GIGAB2B as early as possible by accessing: Buyer Central — APIs — Connection Options — Open API to obtain a new API Key.

# Signature Rules
Prerequisites: Buyers must first obtain an API Key from GIGAB2B, which consists of the Client ID and Client Secret provided on the Connection Details page. Sellers need to contact Marketplace Customer Service for Open API connection and their Client ID and Client Secret. Note that Client ID a
nd Client Secret must be in the production environment.
1.Construct String 1: Concatenate the API Key, API path, timestamp (from the request header), and nonce (random value) using "&" as the delimiter. Example: Client ID&API path&timestamp&nonce
2.Construct the Secret Key: Concatenate the Client ID, Client Secret, and the nonce (from the request header) using "&" as the delimiter. Example: Client ID&Client Secret&nonce
3.Use the secret key to perform an HMAC-SHA256 encryption on String 1, and then convert the result into a hexadecimal string to obtain Ciphertext 1
4.Sign Value: Encode Ciphertext 1 in Base64 to obtain the final signature (sign), which is passed as an input parameter.

# Response Parameters
GIGAB2B has established a similar response parameter structure for each interface. Except for a few interfaces that may include additional parameters, the interface structure follows the table below:
Parameter Name Data Type Required ? Description Default Value
success bool YES Determining request success
code string YES Status Code: Returns 200 for success, or the corresponding
error code for failures.
data object] NO Information about the request response.
requestld string YES A unique identifier to help client-side track and handle
exceptions.
msg string YES Error message: Returns "success" on success, or an error
description on failure.
subMsg string NO Error details scenario description: returns when the response
fails and includes a secondary error.
recommend string NO Error Diagnostics URL: Client can directly copy the URL to
navigate to the error diagnostics page (refer to the "Error
Codes" section in the API documentation) for quick issue
resolution.
